# Admin panel deep audit, 28 Oct 2026 (second pass)

Scope: all 17 `/admin` pages, the 2 `/health/admin` pages, all 34 `/api/admin` routes, the health
admin APIs (`/health/api/monetization/*`, `/health/api/earn/stats`), the proxy's role gate, and the
blood report analyser admin from #144. Evidence: the code on `main` (83384c1), read-only queries on
the production database, and the full test suite on a local Postgres (138 files, 1,070 tests, all
passing before any change). The live admin needs Google sign-in, so production screens were not
clicked; findings are from code and live data.

The first pass (`docs/admin-audit/2026-10-28.md`, PRs #138 and #139, both merged and live) is not
repeated here. Its fixes were re-checked and still hold.

## The uncomfortable part first

1. **One click still sends the old no-consent offer to 1,368 people.** The imported-list campaign
   from 19 Oct left 1,368 WhatsApp and 146 email messages "cancelled" in the outbox. Growth →
   Messages shows them in history with a **"Move back to To send"** link, and the sender does not
   check consent at send time. Click it (or several) and the next batch sends them. #138 blocked
   *new* campaigns to the imported list, but not reviving the old ones. Live count, 28 Oct:
   `imported / whatsapp / cancelled = 1,368`, `imported / email / cancelled = 146`.
2. **Desk-agent limits only exist on paper.** The only role check is the URL list in the proxy. A
   desk agent is allowed into all of `/api/admin/growth`, which also runs "Run daily now" (sends
   every queued message), "Post today's Reel", deletes members, sends diet plans and changes
   paid clients' access. They can also open `/health/admin/earning` (all revenue) and export every
   contact as CSV. Today there is one admin (you, owner), so nobody can misuse this yet, but it
   breaks the day you add a desk agent.

## Findings

Severity: **Critical** = harms customers or breaks a rule today. **High** = real gap, not yet
exploited. **Medium** = wrong behaviour in an edge case. **Low** = tidy-up.

### Consent and messaging

| # | Severity | Finding | Evidence | Fix |
|---|---|---|---|---|
| C1 | Critical | Cancelled messages from a no-consent campaign can be moved back to "To send", and the sender sends them | `markOutbox()` accepts any id → `pending`; `dispatch()` only checks opt-outs, bounces and caps, never the campaign's segment. 1,368 + 146 such rows live | PR 1: the sender cancels any campaign message whose campaign targets a no-consent segment; "Move back" refuses them with a plain reason |
| C2 | Medium | A Contacts list ("List: x") lets in people known only from the imported sheet plus a WhatsApp chat | `recipients("tag:…")` keeps anyone with any kind other than `imported`, so `imported + chat` passes. No built-in segment includes chat-only people. 2 such people live | PR 1: lists keep only people with a consent kind (member, ex-member, lead, paid customer, subscriber) |
| C3 | Owner decision | Re-uploading the old sheet **with End dates** turns those people into members, who then get campaigns, win-back and review asks | Audience import and `/api/admin/members/import` put dated rows on the member list with no consent record. This is also how you were told to load the real register | Not changed. Decide: is the register you upload people who agreed to messages? If not, they should get renewal reminders only, not offers |

### Roles and access

| # | Severity | Finding | Evidence | Fix |
|---|---|---|---|---|
| R1 | High | Desk agents can run every Growth action | `team-core.ts` lets agents into `/api/admin/growth`; the route checks only `isAdmin()`. Actions: `run-daily`, `post-reel`, `delete-member`, `diet-send`, `diet-regenerate`, `diet-stage`, `client-access`, `version-reject`, `apply-order` | PR 2: agents keep members, leads and today's messages; the rest need manager or owner |
| R2 | High | Desk agents can open the health admin: earnings, health sync, monetization orders/leads/analytics | Those paths are outside `/admin`, so the proxy's role gate never runs; they check `isAdmin()` only | PR 2: owner or manager required |
| R3 | Medium | Desk agents can export every contact (name, mobile, email) as CSV | `/api/admin/contacts?export=1` is in the agent area | PR 2: export needs manager or owner |
| R4 | Medium | Desk agents can bulk-import members | `/api/admin/members` and the Audience upload | PR 2: import needs manager or owner (the Audience page is already closed to agents) |
| R5 | Medium | Members' saved blood reports are owner-only in the proxy only | `/api/admin/blood-report/reports` checks `isAdmin()`; if the proxy matcher ever changes, managers get health data | PR 2: the route itself requires owner |

### Data safety

| # | Severity | Finding | Evidence | Fix |
|---|---|---|---|---|
| D1 | Medium | Deleting a member is a hard delete that also wipes their referral rewards | `deleteMember()` → `delete from members`; `referral_rewards` cascade. ### Correctness

| # | Severity | Finding | Evidence | Fix |
|---|---|---|---|---|
| B1 | Low | Blood report "people with access" counts expired grants | `usage()` counts `revoked_at is null` without the expiry check that `accessList()` uses | PR 3 |
| B2 | Low | Blood report access ends by the database's UTC date, up to 5½ hours after midnight in India | `current_date` in `accessList()`/`usage()` | PR 3: use India's date |
| B3 | Low | Some admin routes return raw database error text to the browser | `content` PUT, `diet-pro/*`, `growth/diet-plan` POST, `library` POST | PR 3: log it, show a plain message |

### Checked and fine

- Every `/api/admin` route checks the session before doing anything; owner-only Team checks the role in the route too.
- Every write from another site is refused (origin check in the proxy for all APIs).
- WhatsApp media proxy only accepts numeric ids; uploads sniff real image/PDF bytes.
- Campaign create, recurring runs, "Everyone", Meta export: imported list refused (#138).
- Leads segment skips anyone who paid (#139); Instagram DM coach alerts live (#139).
- Blood report: viewing a member's reports needs a written reason and is logged before the read.
- QR SVG rendering uses a library string, not user input.
